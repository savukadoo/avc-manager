# Toyota 1GD custom PID research — 2018 Fortuner automatic

Reviewed **22 November 2026**. The owner confirms **2018 Fortuner, 2.8 diesel, automatic**. Exact transmission model, delivery market, build month and ECU calibration have not been read or confirmed. The initial research made no additional ECU requests. Implementation status is recorded below; research candidates remain distinct from readings validated on this vehicle.

## Recommendation

There are useful, original community results for the earlier 1GD generation. Prioritise **ATF pan/converter temperature, DPF accumulation, three EGT channels, and gear/lock-up** for a separately validated read-only profile. Fuel pressure, DPF state and injector corrections are second-stage candidates. Do not import a complete forum CSV or treat a shared engine name as proof of the same ECU layout.

Toyota's own DPF booklet separates Hilux/Fortuner systems before/after May 2020 and Prado systems before/after August 2020. Forum authors also distinguish the earlier 130 kW ECM/addressing from the later 150 kW version. These are related but different boundaries: retain model, build date, hardware/calibration and market in the profile identity. [Toyota Australia booklet, dated March 2021](https://www.toyota.co.nz/globalassets/owners/dpf/tso2021_01.pdf)

## Candidate definitions and validation order

Notation: **A is the first data byte after the positive response service and identifier** (`61 82`, `61 38`, `41 78`, etc.), not a CAN header, ISO-TP length/sequence byte or message-count prefix. `U16(X,Y)=256×X+Y`. The table is a research shortlist, **not commands enabled in the live app**.

| Priority / metric | Read request; expected source | Candidate decode / unit | Confidence and per-candidate check |
| --- | --- | --- | --- |
| 1 · ATF pan and converter outlet | Service `21`, identifier `82`; `7E0 → 7E8`, positive `61 82` | **Pan `A−40`; converter `C−40`, °C**. S1/S8 support integer decoding. | Strongest ATF candidate. S1's `4E C0 56 40` payload decodes to 38/46 °C; do not use the older two-byte formula automatically. Compare both channels with a known scan tool from cold soak through warm operation. Confirm actual six-speed transmission first. |
| 1 · DPF PM accumulation | `21 / 38`, `7E0 → 7E8`, `61 38` | **`2×J`, %**; J is byte 10. S4/S5; S9 independently contains that layout. | Medium-to-strong candidate, no Fortuner measurement here. Preserve values above 100; this is an ECU accumulation ratio, not a physical fullness percentage with a universal 100% ceiling. Compare against the same ECU's Techstream parameter through a naturally occurring cycle; do not force one. |

## Oil and engine temperature follow-up — 22 November 2026

AVC Manager already implements standard **coolant `0105`**, **intake air `010F`** and **engine oil `015C`**, but only ECU-discovered supported sensors are polled. An entry in the registry is not proof of support on this vehicle. “Engine temperature” should be labelled coolant when that is the actual measured quantity.

A further search found an additional **unverified** engine-oil lead in [OBDb's original Fortuner definitions](https://github.com/OBDb/Toyota-Fortuner/blob/main/signalsets/v3/default.json): header `7E0`, response `7E8`, request `2151`, signal `FORTUNER_EOT`, an eight-bit field at data bit 72 with offset −40 °C. The command is explicitly `dbg:true`. The same reply definition separately names VVT oil temperature and previous-trip engine-oil temperature; these are distinct parameters. The file mixes Toyota generations and engines and does not establish 2018 1GD applicability. A diesel without the corresponding measurement must not inherit a petrol/VVT interpretation simply because the response matches a request identifier.

[The parameter publisher](https://pelican.clutch.engineering/cars/toyota/fortuner/parameters) marks this engine-oil signal **Tester needed** for 2018. Its general Fortuner page records support data only for 2021–2022, which does not validate this signal on a 2018 diesel. The separate `700 / 221F5C` engine-oil definition is also debug-marked and is not promoted as an earlier-1GD fallback. Another signal ID containing `EOT` (`FORTUNER_EOT_700`, request `22107B`) is actually named **Intake air temperature**; do not identify channels from the ID alone.

The original JSON was retrieved directly on 22 November 2026 after the web renderer could not open it; SHA-256 `5e4fcd1b470d1a01ea893f5193f00762fd478868dd643ef340cb215f6bad54d5`. A source commit was not pinned. The repository is CC BY-SA 4.0. No definitions were copied into production, no command allowlist was changed, and no new request was sent to the car. This updates the shortlist with a lead; the conclusion remains that **engine-oil temperature on this exact Fortuner is unconfirmed**. Transmission oil temperatures (`2182`) and EGT (`0178`) remain separate measurements, not substitutes for engine-oil temperature.

## Conflicts that must remain visible

- **ATF scaling:** S4's December 2018 two-byte equation is algebraically `U16(A,B)×7/1800−40` (converter C/D). S1 supports integer `A−40` / `C−40`. For S1's sample, integer pan decoding gives 38 °C, the older equation 38.4 °C, and fractional `U16(A,B)/256−40` gives 38.75 °C. These differences need reference/precision validation, not averaging. S5 also transposes the converter request identifier; reject that transcription as unverified.
- **DPF pressure encoding:** a first-hand **2015 1GD Prado** KOEO capture on **18 Jan 2018** reports `017A` data beginning `01 7F F8 …`. Offset decoding of B/C gives −0.08 kPa; signed-16/100 gives +327.60 kPa. That is an explanatory calculation, not a measurement from the user's car. [Original Torque discussion and raw response](https://torque-bhp.com/community/main-forum/default-pid-equation/)
- **DPF scale:** S3 reports users choosing ×1 or ×2 and different cycle values. Preserve the raw byte, chosen named parameter and reference comparison. No clamp-to-100 or generic “blocked” alert.
- **2018 date ambiguity:** a post written in 2018 may describe a 2015/2017 vehicle; a modern forum signature may have changed. The explicit S2 2018 confirmation is stronger than inferring applicability from a timestamp.
- **Later ECMs:** S7's `700 / 22xxxx` family and the vendor's MY2021 updates are not fallback requests to cycle through on a 2018 vehicle. Toyota's own documented DPF production split reinforces the need for a separate later-model profile. Do not combine LC200 1VD, older 1KD, petrol V6, Prado 250 eight-speed or later 48 V variants with this shortlist.

## Source provenance and reuse

Forum authors publish facts, equations and reports, but no reusable software/data licence was established for the forum tables. Cite the original authors and derive an independently reviewed small profile; do not copy prose, attachments or entire CSVs into the app. The commercial ScanGauge table is also reference material, not an open-source package.

OBDb's Hilux repository uses **CC BY-SA 4.0**. Its `2138` row agrees on byte index 72/multiplier 2 but remains debug-marked. `700 / 221627` and `221628` ATF rows have different formatting and inconsistent year filters; they are not proof for a 2018 1GD. Preserve attribution/share-alike obligations if definitions are reused and pin an audited commit before use; this review did not obtain a commit SHA. ## Validation plan before any app change

1. Confirm vehicle build/delivery details, actual transmission model and ECU identification/calibration where available. Do not request or publish the owner's full VIN merely for forum matching.
2. Agree a **small named read-only test set** with the implementation owner. No bulk scanning, imported command buttons, session changes, coding, DTC clearing or DPF actuation. Several useful threads mix monitoring definitions with commands that change the vehicle; those must stay excluded.
3. Validate decoding locally using source captures and malformed/short/negative/multiple-ECU/ISO-TP fixtures. New `21` response support must not loosen the production command boundary into an arbitrary terminal. Verify a response's source and identifier before any offset/formula is applied.
4. Later, only when separately authorised, collect a bounded set of raw responses and reference-tool readings from this exact vehicle, retaining units, conditions and timestamps locally. Test one request group at a time at conservative rates. Do not drive or trigger regeneration just to manufacture validation conditions.
5. Promote only confirmed channels, with a profile/version and evidence. A positive response alone proves transport support, not the formula or physical sensor identity. No response/negative reply remains “not available in this test”, not universally unsupported. This also applies to the current missing Permanent-DTC response.

The existing generic allowlist and installed app were left unchanged by this research. [ELM Electronics framing/header reference](https://www.elmelectronics.com/wp-content/uploads/2016/07/ELM327L_Data_Sheet.pdf)

## Expanded experimental DPF profile — 0.4.1

The owner authorised adding the remaining monitoring candidates for testing before deciding which to retain. This build adds fifteen registered readings: three017A pressure fields, two017C temperature fields, five018B aftertreatment fields,2104 Toyota pressure, and four extra fields from the already queried2138 response. Existing accumulation and EGT1/2/3 bring the DPF page to nineteen channels. Successful decoding makes a channel selectable; refusals, absent flags and incomplete replies remain visible. This is a local candidate, not proof of physical ECU support.

[SAE-authored J1979-DA October2011, public PDF copy](https://f30.bimmerpost.com/forums/attachment.php?attachmentid=1800282&d=1523076762), tables B102/B104/B118, establishes017A differential pressure as **signed16/100kPa**, inlet/outlet pressure as unsigned16/100kPa,017C temperatures as unsigned16/10−40°C, and018B per-field flags. The018B averages are minutes and kilometres between successful active events, not counters since the last event. B1 distinguishes active/passive regeneration, not automatic/manual initiation. These earlier standard definitions are not assumed to be implemented by this vehicle.

The [original earlier-130kW post](https://www.newhilux.net/phpbb/viewtopic.php?t=45103) supplies the explicitly unverified2104 and2138 interpretations. The017A signed encoding conflicts with earlier Toyota offset interpretations; pressure details show the offset alternative alongside raw bytes, without automatically changing the SAE decoder. Catalyst-restriction units/range also remain a conflict: the community uses a0.001 offset scale while the manufacturer's data-list range is approximately±4. It is labelled an experimental index, with no diagnosis threshold. Service-regeneration state remains separate from018B live regeneration status.

Only one new manufacturer request,2104, is permitted. The direct standard check set is fixed to017A/017C/018B and is restricted to the enabled earlier Toyota profile on7E8/11-bit CAN. All traffic retains the four-query/second cap, cancellation and functional-header restoration. No raw terminal, ECU write or forced-regeneration action is added.

Unmapped ECU ash mass, total regen count and last-event time/distance are shown as **Not mapped · no query sent**. A separate connection-local observer counts only contiguous explicit018B status transitions and estimates distance from fresh speed samples. Starting mid-cycle does not count a complete event. Gaps over30s in regen status, or15s in speed, invalidate distance; reconnecting starts a new session. These observations never stand in for ECU lifetime counters. **Save report** writes a local CSV of sample/check outcomes, definitions, raw replies and observation coverage for later review.

The revised dashboard uses one DPF category with accumulation as its primary stat. The graph window contains the related metric selector; browsing it preserves the saved dashboard card. The standalone DPF page retains all check outcomes and explicitly unmapped counters for testing.
