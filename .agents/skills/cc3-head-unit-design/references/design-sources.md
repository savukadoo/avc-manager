# Design sources

Use these selectively when a particular decision needs more evidence. The workflows here are an original synthesis and can be applied directly to the project's Java Views.

| Source | What to carry into a head unit |
|---|---|
| [Visual Design Foundations](https://github.com/wshobson/agents/blob/main/plugins/ui-design/skills/visual-design-foundations/SKILL.md) | Define roles for type, surfaces, spacing and icons. Give controls with the same purpose the same visual weight. Translate any web dimensions to the measured Android window. |
| [Impeccable](https://github.com/pbakaus/impeccable) | Critique the reading order on actual screenshots. Rank issues by how much they interfere with a task. Recheck the same screenshots after adjusting hierarchy, spacing or wording. |
| [MockFlow Automotive HMI Infotainment](https://mockflow.com/skills/automotive-hmi-infotainment) | Compare wireframes for competing map, media and control layouts early. Use representative parked and driving tasks and real labels. The composition exercise can be done locally. |
| [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) | Compare palette and type options on the same populated screen. Carry chosen roles into Android Views and check every interaction state. |
| [Android for Cars sizing](https://developers.google.com/cars/design/automotive-os/design-system/sizing), [colour](https://developers.google.com/cars/design/automotive-os/design-system/color) and [Android Views accessibility](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views) | Calibrate driving targets and contrast, then measure the result. Keep the native Android 10 launcher lifecycle and the TEYES system bar in the design. |
